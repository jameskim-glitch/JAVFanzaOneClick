# JAV FANZA OneClick 1.12.0

공개용 소스에서는 외부 제작사별 CID 변환표를 제거하고 일반 품번 형식과 FANZA 검색 응답으로 식별번호를 확인합니다. 제작사별 예외·접미사·Blu-ray 품번의 검색률은 기존 설치본과 다를 수 있습니다. 자세한 변경점은 [README](README.md)를 참고하세요.

Windows 64비트용 단일 Stash 플러그인입니다. 별도의 Python, Stash 스크레이퍼, Chrome 확장 프로그램, AVDBS 로그인이 필요하지 않습니다.

## 설치

1. 설치 프로그램 `JAVFanzaOneClick_Setup_1.12.0_Windows_x64.exe`를 실행합니다. 기존 버전 위에 설치해도 캐시와 설정은 보존됩니다. ZIP을 사용하는 경우 `JAVFanzaOneClick` 폴더를 Stash의 플러그인 폴더에 복사합니다. 기본 경로는 `%USERPROFILE%\.stash\plugins`입니다.
2. Stash에서 **Settings → Plugins → Reload Plugins**를 누릅니다.
3. 화면을 새로고침합니다. 새로 스캔되어 생성되는 장면은 자동으로 처리됩니다.

## 1.11.0 폴더 이름 자동 태그

- 스캔으로 **새로 생성되는 장면**에 라이브러리 루트 및 하위 폴더 이름과 일치하는 **기존 태그**를 자동으로 추가합니다. 품번이나 FANZA 조회 성공 여부와 무관하게 별도 실행합니다.
- 파일 이름, 라이브러리 바깥 상위 폴더, 태그 별칭은 비교하지 않습니다. 글자·공백이 같은 폴더 이름만 사용하며 영문 대소문자와 유니코드 조합 차이는 허용합니다. 자동 태그 제외 설정과 이름 충돌은 건너뜁니다. 새 태그는 자동 생성하지 않습니다.
- **설정 → 작업 → Plugin Tasks → 폴더 태그 누락 검사 / 폴더 태그 누락 채우기**로 기존 장면을 검사하거나 보완합니다. 최초 변경 전에 DB·이미지 전체 백업을 한 번 만들고, 이미 완료된 항목은 건너뜁니다. 일괄 작업 중에는 스캔·폴더 이동·태그 규칙 편집을 멈추세요.
- 기존 태그를 교체하지 않고 누락 태그만 추가합니다. 원본 영상·제목·설명·배우·제작사는 수정하지 않습니다. 기록은 `data/folder_tags`에 보관합니다. 새 장면마다 전체 백업을 만들지는 않습니다.
- 기존 장면의 폴더 이동이나 수동 태그 삭제에는 자동 재적용하지 않습니다. 필요할 때 누락 채우기를 실행하세요. 배우 화면의 세 버튼 구성은 그대로 유지합니다.

## 1.10.0 제작사 연결·안전한 병합·반복 작업 최적화

- **설정 → 작업 → 제작사 이름·StashDB 연결 정리**: StashDB의 실제 제작사 목록과 일본어 별명을 대조합니다. 공식 사이트로 확인한 일부 일본어 표기도 지원합니다. 하나로 확인된 항목만 표준 이름·StashDB ID로 연결하고, 기존 이름과 별명·주소는 보존합니다. 동명이사·레이블 혼동·출처 번호 충돌은 자동 확정하지 않습니다.
- **설정 → 작업 → 동일 StashDB 제작사 병합**: 연결 정리 후 같은 StashDB UUID가 확인된 중복만 합칩니다. 실제 첫 변경 직전 DB·이미지 전체 백업을 한 번 만들고, 영상·이미지·갤러리·그룹 및 하위 제작사 연결을 이동한 후 확인합니다. 연결이 남거나 통신 결과가 불확실하면 원본 삭제를 중단합니다. 충돌하는 상위 제작사·사용자 정의 필드가 있으면 보류합니다. 영상 파일 자체는 삭제하지 않습니다.
- 병합 중에는 다른 편집·스캔을 멈추세요. Stash API는 여러 단계 병합을 하나의 트랜잭션으로 제공하지 않습니다. 중단 시 `data/studio_sync`와 `data/studio_merges`의 기록을 확인하고, 확인 없이 재실행하지 마세요. 전체 복원은 백업 이후의 다른 편집도 되돌릴 수 있습니다.
- 최초 제작사 목록 조회는 수분 걸릴 수 있으며 진행 건수를 로그에 표시합니다. 목록은 7일간 캐시합니다. Stash 설정의 StashDB API 키를 메모리에서 읽어 **고정된 StashDB 주소에만** 사용합니다. 키를 캐시·배포 파일에 저장하지 않습니다. 친구는 자신의 StashDB 연결을 설정해야 합니다.
- 연속 느낌표 등의 공백 차이로 완료 항목이 계속 미처리로 잡히던 문제를 수정했습니다. 원본 정보가 부족한 미완료 항목은 24시간 재시도 간격을 두며, 항목 수정이나 명시적 강제 실행으로 우회할 수 있습니다.
- 기존 장면 표지는 자동·강제 텍스트 정리에서 보존합니다. Stash의 실제 표지 누락 필터로 빈 항목만 채웁니다. 표지 덮어쓰기는 별도 명시적 `replace_cover` 요청에서만 허용합니다.
- **이미지 전체**는 StashDB 연결을 먼저 이용해 빈 사진·로고를 채우고 FANZA로 보완합니다. 전체 장면 대신 해결되지 않은 빈 항목과 연결된 장면만 조회합니다. 기존 사진은 덮어쓰지 않습니다.
- 바뀔 내용 없는 배우 재스크래핑은 전체 백업을 만들지 않습니다. 고화질 비교용 크기·지문만 30일 캐시해 같은 작은 원본의 반복 다운로드를 줄입니다. 캐시는 최대 10,000건이며 실제 적용할 원본은 다시 확인합니다.
- 중복 작업 버튼은 실행 중 작업 ID를 재사용하고, 장면·이름 생성 작업은 동시 실행을 막습니다. 화면 이동 감지로 툴바를 갱신하여 1.2초 반복 타이머를 없앴습니다. 배우 화면의 세 버튼 구성은 유지합니다.
- 만료된 임시 미리보기만 정리합니다. 사진 복구 이력·병합 기록·전체 백업은 플러그인이 자동 삭제하지 않습니다. 기존 백업 정리는 사용자 동의에 따른 별도 관리 작업입니다.

## 1.9.1 배우 화면 버튼 정리

배우 목록·상세 화면의 버튼은 **이미지 전체 → 미처리 전체 → 사진·로고 업데이트** 세 개만 표시합니다. 자동 처리 표시도 배우 화면에서는 숨깁니다. 장면·제작사 화면의 버튼과 새 장면 자동 처리는 기존대로 유지합니다.

배우 이름 정리와 영문 별명 재스크래핑은 **Settings → Tasks → Plugin Tasks**에서 실행할 수 있습니다. 중복 배우 검사 버튼은 배우 화면에서 제거했으며 기존 배우 정보·병합 기록은 유지합니다.

## 1.9.0 영문 별명으로 이름 변경 후 StashDB 재스크래핑

1. **Settings → Tasks → Plugin Tasks → 영문 별명으로 이름 변경 후 StashDB 재스크래핑**을 실행합니다.
2. 전체 배우의 영문 별명을 이름으로 올리고 StashDB 정보를 가져옵니다. 기존 사진은 보존하고 빈 사진을 채웁니다.
3. Tasks와 로그에서 진행·결과를 확인하고, 완료 후 화면을 새로고침합니다. 기존 사진의 갱신·구도 선택은 **사진·로고 업데이트**에서 진행합니다.

- **실제 표시 이름을 영문으로 변경합니다.** 원래 한국어·일본어 이름은 별명에 남기므로 이전 이름으로도 검색할 수 있습니다.
- 기존 영문 별명을 사용합니다. 같은 이름이 StashDB에 성·이름의 반대 순서로 등록되어 있으면 StashDB 표기 순서를 사용합니다. 번역기나 한국어 역음역으로 새 영문 이름을 만들지 않습니다.
- Stash에 설정된 StashDB 스크래퍼로 다시 조회합니다. 기존 StashDB ID가 있으면 그 ID를 우선 사용하고, 없으면 영문 별명의 전체 이름을 대조합니다. 검색 결과가 없거나 여러 배우가 일치하면 기존 영문 별명을 이름으로 올린 뒤 정보 스크래핑만 보류하고 로그에 남깁니다. 기존 StashDB 연결과 프로필이 충돌하면 해당 항목 전체를 건너뜁니다.
- 영문 별명이 없는 배우는 건너뜁니다. 기존 영문 이름인 배우도 재스크래핑할 수 있습니다. 영문 예명이 한 단어이고 StashDB 연결도 없으면 FANZA 번호 또는 생년월일 일치가 필요합니다.
- 일치하는 항목의 StashDB ID, 별명·출처 링크와 빈 프로필 정보를 저장합니다. 이후 고화질 사진·로고 업데이트에서 배우를 직접 연결할 필요가 줄어듭니다.
- 시작 전에 Stash DB와 이미지 백업을 만듭니다. 백업 경로는 Stash 로그의 `Successfully backed up database to` 줄에서 확인할 수 있습니다. 개별 변경 전 정보와 사진 기록은 `data/stashdb_rescrape`에 남깁니다.
- 사진 갱신을 선택하면 출처 후보 최대 24개 중 실제 이미지 크기를 비교해 더 큰 원본을 사용합니다. 기존보다 짧은 변이 작아지는 사진은 보존합니다. 전신 여부는 자동 판정하지 않으며 원하는 구도는 기존 **사진·로고 업데이트**에서 선택할 수 있습니다.
- 사용자가 입력한 기존 프로필 정보, 즐겨찾기, 평점, 태그, 영상·장면 연결은 유지합니다. 배우를 새로 만들거나 합치지 않습니다. 작품 제목·설명·표지와 제작사 정보는 이 작업의 대상이 아닙니다.
- 저장 결과가 불확실하면 작업을 중지하고 결과 로그를 남깁니다. Tasks의 **Stop**으로 중단한 경우에도 이미 완료된 변경은 유지됩니다.
- Stash 설정의 StashDB 연결과 인터넷 접속이 필요합니다. 별도의 플러그인용 API 키를 입력하지 않습니다.

## 1.8.0 원본 사진·로고 업데이트와 남은 이름 교정

### 원본 사진·로고

1. 배우 또는 제작사 목록에서 **사진·로고 업데이트**를 누릅니다. 상세 페이지에서 열면 현재 항목을 먼저 선택합니다.
2. 항목을 고르고 **원본 후보 조회**를 누릅니다. Stash에 연결된 StashDB와 해당 항목의 StashDB ID가 필요합니다. 친구에게 개인 API 키를 공유하지 마세요.
3. 원하는 사진의 **원본 비교**를 누릅니다. 현재 사진과 새 원본의 실제 픽셀 크기를 함께 표시합니다.
4. 같은 인물·제작사인지, 원하는 구도인지 확인한 뒤 체크하고 **기존 원본 보관 후 교체**를 누릅니다.
5. 기존 사진이 있었다면 같은 결과 화면에서 확인 체크 후 **이전 원본 복원**을 사용할 수 있습니다. 이후 다른 사진으로 바뀌었다면 덮어쓰지 않습니다. 목록 표시는 직접 새로고침하세요.

- 이름 검색 첫 결과를 쓰지 않고 연결된 StashDB UUID가 정확히 일치하는 원본만 사용합니다. 연결 없음·여러 번호·프로필 충돌·원본 없음은 설명하고 중지합니다.
- **전신 여부는 자동 판정하지 않습니다.** 원본 후보에서 직접 전신 구도를 확인해 선택하세요. 세로 사진을 전신이라고 단정하거나, 얼굴 사진을 늘리거나, AI로 몸을 만들어 넣지 않습니다.
- 원본 바이트를 그대로 전달하며 자르기·확대·재압축을 하지 않습니다. Stash가 반환하는 저장본을 다시 읽어 확인합니다. 사진 한 장은 최대 5MB·1,600만 화소, 후보는 최대 24개까지 지원합니다.
- 현재보다 총 픽셀 또는 짧은 변이 작아지는 사진은 별도 동의가 있어야 교체합니다. 같은 원본은 재저장하지 않습니다.
- **배우 목록에서도 사진 전체 보기**를 기본 적용합니다. 원본 비율을 유지하므로 여백이 생길 수 있습니다. 업데이트 창의 체크를 끄면 기존 표시로 돌아갑니다. 영상·장면 표지 표시에는 적용하지 않습니다.
- 기존 원본과 변경 전 정보는 플러그인의 `data/image_history`에 보관합니다. 크기에 따라 저장 공간이 필요합니다. 비교용 작은 기록은 `data/image_previews`에 저장하며 미리보기는 30분 후 만료됩니다.
- 작업 중 다른 이미지·메타데이터 편집은 잠시 멈춰 주세요. 미리보기 뒤 정보나 사진이 바뀌면 중단하지만, Stash API에는 원자적인 조건부 이미지 갱신 기능이 없어 마지막 확인 직후의 외부 수정까지 막을 수는 없습니다.
- 저장 응답을 잃으면 자동 재시도하지 않습니다. 원본 기록과 현재 Stash 사진을 확인하세요. 복원 버튼은 해당 결과 창에서 제공되며 창을 닫은 뒤에도 원본 기록은 남습니다.
- 기존 **이미지 전체**와 자동 처리의 ‘빈 이미지만 채우기’는 그대로입니다. 기존 사진의 일괄 자동 덮어쓰기는 하지 않습니다.

### 배우 한 명의 이름 교정

- 공식 이름·읽는 법에 괄호로 옛 예명이 함께 오는 경우 현재 이름과 각 예명의 발음을 분리합니다. 뜻 번역은 하지 않습니다.
- 예: `似鳥（似鳥日菜）` → 현재 이름 `니토리`, 옛 예명 `니토리 히나`; `真田さな（真田美樹、真田みづ稀）` → 현재 이름 `사나다 사나`와 확인된 예명들.
- **사진·로고 업데이트 → 배우 선택 → 이 배우 이름 발음 확인**에서 쓸 표기를 고르고 체크 후 **선택한 이름 적용**을 누르세요. StashDB 연결 없이도 FANZA 배우 링크 하나가 확인되면 사용할 수 있습니다.
- 이전 이름·원명·영문 발음·확인된 예명은 별칭으로 남깁니다. 이름 변경은 사진·장면·태그를 수정하지 않습니다. 변경 전 기록은 `data/performer_names/manual_history`에 보관합니다.
- 이 화면에서 직접 선택한 표기는 사용자 지정으로 기록하여 이후 자동 이름 정리에서 보존합니다.
- 기존 **배우 이름 정리**도 괄호 발음을 처리합니다. 이전 자동 번역 기록과 일치하는 이름은 교정하고, 기록 없는 사용자 한국어 이름은 보존합니다. 남은 오역은 위의 개별 확인 기능으로 고치세요.

## 1.7.1 백업 성공 응답 처리 수정

- Stash 0.31.1은 서버에 백업을 저장할 때, 성공해도 API 응답에 파일 경로 대신 `null`을 반환합니다. 1.7.0이 이를 오류로 오인해 병합 직전에 멈추던 문제를 수정했습니다.
- 정상 GraphQL 응답의 명시적인 `backupDatabase: null`을 백업 완료로 처리합니다. 응답 필드 누락·잘못된 형식·GraphQL 오류·통신 오류는 여전히 병합을 막습니다. HTTP 200만으로 성공으로 판단하지 않습니다.
- 경로를 반환하지 않는 경우 백업 완료와 경로 확인 방법을 표시합니다. 실제 파일 경로는 Stash 로그의 `Successfully backed up database to` 줄에서 확인할 수 있습니다.
- 백업·이력 저장·사진 준비 단계에서 중지한 경우에는 **병합하지 않았습니다**라고 안내합니다. 병합 요청 후 응답을 잃은 경우에는 결과 불확실 안내를 표시합니다.
- 1.7.0의 해당 오류에서 만들어진 백업은 지우지 않습니다. 새 버전 설치 후 다시 검사·미리보기·확인하면 새 백업을 만든 뒤 병합합니다.

## 1.7.0 중복 배우 검사·확인 후 병합

- **배우 목록 → 오른쪽 아래 중복 배우 검사**를 누릅니다. 검사와 미리보기는 Stash 데이터를 변경하지 않으며 외부 사이트에도 조회하지 않습니다.
- **식별번호 일치**: 같은 FANZA 배우 번호, 또는 같은 Stash-box 출처의 같은 UUID입니다. 실제 동일인인지 사진과 정보를 확인한 뒤 병합하세요.
- **이름·별칭 확인 필요**: 한글 띄어쓰기, 대소문자, 영문 성·이름 순서, 원명·괄호 안 옛 예명이 일치합니다. 이름만으로 동일인을 확정하지 않으며, 사진·프로필을 직접 비교해야 합니다.
- **정보 충돌**: FANZA/Stash-box 식별번호, 생년월일 또는 성별이 다릅니다. 플러그인 병합을 차단합니다. 번호·프로필을 먼저 확인하세요. 같은 배우에게 오래된 번호가 여러 개 있는 경우도 보수적으로 차단합니다.
- 짧은 예명·철자가 비슷하다는 이유만으로는 후보를 만들지 않습니다. 20명을 넘는 항목이 공유하는 이름/번호는 제외하고 그 수를 표시합니다. 한 번에 후보 500쌍까지 표시합니다.
- 후보는 **두 명씩** 비교합니다. A-B, B-C가 비슷하다는 이유로 A-B-C를 통째로 합치지 않습니다. 처리 후 다시 검사하면 목록이 갱신됩니다.
- **남길 배우 선택 → 병합 미리보기 → 동일인 확인 체크 → 백업 후 이 두 배우 병합** 순서입니다. 자동/일괄 병합은 없습니다.
- 남길 배우의 이름과 기존 사진은 유지합니다. 남길 배우의 사진이 비어 있으면 다른 항목의 저장된 사진을 복사합니다. 별칭·출처 링크·Stash ID·설명은 모으고, 빈 프로필 정보는 채웁니다. 서로 다른 프로필/사용자 필드 값은 미리보기에 표시하며 남길 항목의 값을 유지합니다. 즐겨찾기와 자동 태그 제외 설정은 하나라도 켜져 있으면 유지합니다.
- Stash 공식 병합 기능으로 장면·이미지·갤러리·기존 배우 태그의 연결을 남길 배우로 옮깁니다. **합쳐진 원본 배우 항목은 제거됩니다. 영상 파일, 장면 제목·설명·태그, 태그 객체는 변경하지 않습니다.**
- **병합 전 Stash 전체 DB와 이미지 blob 백업이 반드시 성공해야 합니다.** 저장된 이미지 용량에 따라 시간이 걸리며 여유 디스크 공간이 필요합니다. 결과 화면에 백업 완료와 경로 확인 방법을 표시합니다. 병합 이력과 변경 전 정보는 플러그인의 `data/performer_merges`에 보존합니다.
- 개별 병합 취소 버튼은 없습니다. 복구 시 Stash 백업 복원이 필요하며, 그 백업 이후의 다른 작업도 되돌아갈 수 있습니다. 큰 작업 전 별도 백업도 권장합니다.
- 미리보기 뒤 수정된 배우는 다시 검사하게 합니다. 백업 후에도 최신 정보를 재확인합니다. 다만 Stash API에는 조건부 병합 기능이 없으므로 병합 중 다른 메타데이터 작업·수동 편집은 중지하세요.
- 통신이 끊겨 성공 여부를 알 수 없으면 자동 재시도하지 않습니다. Stash에서 두 배우의 현재 상태와 백업을 확인한 뒤 다시 검사하세요.
- 1.6.0의 이름 번역 규칙은 이번 버전에서 변경하지 않습니다. 자막 일괄 검색과 고화질 사진 자동 교체 기능도 추가하지 않습니다.

## 1.6.0 배우 이름의 뜻 번역 중단

- 배우 이름에는 일반 번역기를 사용하지 않습니다. FANZA 배우 식별번호로 확인한 **공식 읽는 법 → 로마자·한국어 발음 표기**를 사용합니다. 영문 이름을 번역기에 다시 넣는 방식이 아닙니다.
- FANZA에 공식 영문 이름 필드는 확인되지 않아, 로마자는 읽는 법에서 생성합니다. 공식 영문 예명이라고 주장하지 않습니다.
- 예: `桜空もも → Sakura Momo → 사쿠라 모모`, `海老咲あお → Ebisaki Ao → 에비사키 아오`, `三浦乃愛 → Miura Noa → 미우라 노아`.
- 일본어 원명과 생성한 로마자를 별칭으로 남겨 두 표기로 검색할 수 있습니다. 성·이름의 경계가 확인되지 않으면 억지로 띄어쓰지 않습니다.
- 기존 이름은 **Settings → Tasks → Plugin Tasks → 배우 이름 발음 기준 정리**를 실행하세요.
- 이전 플러그인 번역 캐시와 현재 이름이 일치하면 오역을 교정합니다. 일본어 이름도 발음 기준으로 바꿉니다. 직접 수정한 한국어·영문 이름은 유지하면서 원명·로마자 별칭을 보완합니다.
- 기존 번역 기록이 없어서 자동 생성 여부를 확인할 수 없는 한국어 이름은 보존합니다. 필요한 경우 Stash에서 원하는 이름으로 직접 수정하세요.
- 이전 이름도 별칭으로 보관합니다. 이름 정리 작업은 기존 배우만 갱신하며, 새 배우 생성·병합·장면 제목·설명·사진·태그 변경은 하지 않습니다.
- 공식 발음이 없거나 확인되지 않으면 원래/현재 이름을 유지합니다. 사진 파일명은 공식 발음과 일치할 때만 띄어쓰기 힌트로 사용하며, 발음 출처로 사용하지 않습니다.
- 사람 이름의 통용 한국어 표기와 규칙 기반 음역에는 차이가 있을 수 있습니다. 직접 고친 표기는 이후 작업에서도 보존합니다.
- 새 장면 자동 처리와 **현재 장면 채우기**에도 새 이름 처리가 적용됩니다. 제목·설명 번역과 자막 정책은 기존대로입니다.

## 1.5.0 배우 사진·제작사 로고

- 새 장면 자동 처리와 **현재 장면 채우기**에서 연결된 배우의 프로필 사진, 제작사의 로고도 가져옵니다.
- 장면 화면의 **사진·로고**는 이미지만 처리합니다. 제목·설명·표지·태그·배우 이름은 바꾸지 않습니다.
- 이미 정리해 둔 라이브러리 전체를 채우려면 장면 상세 화면을 나와 **이미지 전체**를 누르세요. 또는 **Settings → Tasks → Plugin Tasks → 배우 사진·제작사 로고 빈 항목 채우기**를 실행하세요. 작업 진행과 저장·보존·미확인·실패 개수는 로그에서 확인할 수 있습니다.
- Stash 기본 실루엣/기본 로고와 실제 저장된 이미지를 구분합니다. **직접 등록했거나 이미 저장된 사진·로고는 덮어쓰지 않습니다.** 다운로드 중 다른 작업이 이미지를 등록해도 저장 직전에 다시 확인합니다.
- FANZA 작품에 연결된 배우·제작사 식별번호와 원어 이름/별칭 또는 FANZA 프로필 링크가 일치할 때만 연결합니다. 같은 이름에 여러 후보가 있거나 기존 FANZA 링크와 충돌하면 건너뜁니다.
- 라이브러리에만 있고 작품 연결이 없는 배우·제작사도 FANZA 프로필 링크가 있으면 처리합니다. 링크도 원어 별칭도 없는 항목은 임의로 추측하지 않습니다.
- FANZA에서 이미지가 제공되지 않거나 접속이 안 되는 경우 빈 상태로 남습니다. 검색 사이트의 다른 사람 사진이나 작품 표지를 대신 넣지 않습니다. 제작사 로고는 원본이 작으면 그대로 작은 해상도입니다.
- 이미지 파일을 실제로 읽어 형식·크기·손상을 검사한 뒤 Stash에 저장합니다. 추가 API 키·Python 설치는 필요 없습니다.
- 사진·로고만 처리한 뒤에는 **화면 새로고침**을 직접 눌러 표시를 갱신합니다. 재생 중인 영상을 자동으로 끊지 않습니다.
- 이미 완성한 장면의 번역 기록은 그대로 인정합니다. 기존 장면의 이미지는 **이미지 전체**를 한 번 실행해 채우세요.

## 이전 1.4.1 점검·개선

- 폴더명이나 설명 속 다른 작품 품번을 잘못 가져오는 문제를 수정했습니다. 직접 지정한 품번 → 영상 파일명 → 장면 제목 순서로 확인합니다.
- 짧은 한국어 제목·설명을 정상 처리합니다. 사용자가 적은 한국어 문장은 유지하면서 태그·프로모션·검열 기호를 정리합니다.
- 잘못된 번역 응답과 손상된 캐시 때문에 작업이 중단되는 문제를 수정했습니다. 긴 일본어를 보조 번역 서비스의 바이트 한도에 맞춰 나눕니다.
- 업데이트 파일을 미리 준비한 뒤 교체합니다. 교체 실패 시 이전 파일을 복원하며, 복원에도 실패하면 복구 파일 위치를 안내합니다.
- **저장된 한국어 자막 다시 연결** 버튼, UTF-16 자막 읽기, 영상보다 긴 자막 안내를 추가했습니다.
- 자막 연결 후 재생이 끊기지 않도록 **화면 새로고침** 버튼을 제공합니다. 플러그인을 다시 불러올 때 이전 버튼·타이머도 정리합니다.

- 현재 장면: 오른쪽 아래 **현재 장면 채우기**
- 기존 장면 전체: 오른쪽 아래 **미처리 전체**, 또는 Settings의 Plugin Tasks에서 **전체 미처리 장면 채우기**

## 기존 한국어 자막 다운로드

- SubtitleCat에서 현재 장면의 품번을 검색합니다. 후보 페이지에 기존 한국어 `Download` 링크가 있을 때만 다운로드합니다.
- 한국어가 `Translate`로만 표시되는 페이지에서는 아무것도 만들거나 번역하지 않습니다. 자막이 없으면 건너뜁니다.
- 검색 결과는 여러 버전일 수 있습니다. 제목과 출처를 보고 후보를 선택하세요. 여러 영상 파일이 있는 장면은 적용할 파일도 선택해야 합니다.
- 영상이 `SONE-458_1080p.mp4`이면 같은 폴더에 `SONE-458_1080p.ko.srt`로 저장합니다. 다운로드 원래 이름의 `-ko`나 국가 코드 `kr`를 새 파일명에 사용하지 않습니다.
- 기존 `.ko.srt`, `.ko.vtt`, `.kr.srt`, `.kr.vtt`가 있으면 보존하고 다운로드를 건너뜁니다. 언어 표시 없는 `.srt`가 정상적인 외국어 자막이면 그대로 두고 별도 `.ko.srt`를 저장합니다. 한국어 또는 언어를 확인할 수 없는 기존 파일은 보존하고 건너뜁니다.
- 이미 `.ko.srt` 또는 `.ko.vtt`를 저장했다면 **자막 찾기 → 저장된 한국어 자막 다시 연결**로 스캔을 다시 요청할 수 있습니다. `.kr` 파일은 자동으로 이름을 바꾸지 않으므로, 한국어로 표시하려면 직접 `.ko`로 맞추세요.
- 정상 SRT 시간과 한국어 대사를 확인한 후 저장합니다. 영상·원본 시간표·자막 대사는 수정하지 않습니다. 대사 내용에 메타데이터 정리 규칙을 적용하지 않습니다.
- 저장한 자막 파일만 대상으로 Stash 스캔을 요청합니다. 연결 후 **화면 새로고침**을 눌러 자막 메뉴를 갱신하세요. 재생 중인 영상을 자동으로 중단하지 않습니다.
- 스캔이 대기 중이면 작업 화면에서 완료 후 새로고침하세요. 자동 연결에 실패해도 파일은 남습니다. 해당 폴더를 선택 스캔하면 됩니다.
- 품번 일치가 영상 길이나 싱크 일치까지 보장하지는 않습니다. 특히 분할·편집 영상에는 그대로 맞지 않을 수 있습니다.
- 사이트에 이미 올라온 자막도 기계 번역일 수 있습니다. 플러그인이 번역 품질을 보증하지는 않습니다.
- 다운로드는 Stash가 실행되는 PC의 영상 폴더에 저장됩니다. 영상 경로에 읽기·쓰기 권한과 인터넷 연결이 필요합니다.
- 자막은 현재 장면에서 수동 검색하는 기능입니다. 새 장면 자동 처리와 **미처리 전체**는 메타데이터와 배우·제작사 이미지를 처리하며 자막을 자동 다운로드하지 않습니다.

## 적용 범위와 보존 규칙

- 품번, 한국어 번역 제목, 발매일, 제작사, 배우, FANZA 링크, 전체 가로형 표지를 가져옵니다.
- FANZA 일본어 제목은 키 입력 없이 한국어로 번역합니다.
- FANZA 일본어 줄거리는 키 입력 없이 한국어로 번역해 `Details`에 넣습니다.
- 설명 앞의 혜택·세트상품·캠페인·세일 안내를 제거합니다.
- `<br>`을 비롯한 HTML 태그와 불필요한 줄바꿈을 정리합니다.
- `○`, `●`, `□`, `■` 등으로 가려진 확실한 일본어 단어를 먼저 복원한 뒤 한국어로 번역합니다.
- 문맥으로 확정할 수 없는 글자는 억지로 추측하지 않고 검열 기호만 제거합니다.
- 번역 뒤에도 남은 `○`, `●`, `□`, `■`, `×` 등의 검열 기호는 최종 제목·설명에서 제거합니다.
- 새 버전에서 정리 규칙이 바뀌면 이전 번역 캐시를 재사용하지 않고 다시 번역합니다.
- 배우 이름은 공식 읽는 법으로 한국어 발음 표기를 만들고, 일본어 원명과 로마자는 별칭으로 남깁니다.
- 기존 한국어·영어 사용자 제목은 유지합니다. 이전 버전이 넣은 일본어 FANZA 제목은 한국어로 갱신합니다.
- 기존 `Details`에 한국어 내용이 있으면 그 문장 자체에서 프로모션 문구와 HTML 태그를 정리합니다. 사이트의 다른 설명으로 통째로 교체하지 않습니다.
- 기존 배우는 보존하고 FANZA 배우를 합칩니다.
- **태그는 생성·수정·삭제하지 않습니다.**
